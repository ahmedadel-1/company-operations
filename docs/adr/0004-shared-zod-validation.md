# ADR-0004: Shared Zod schemas with NestJS 12 native Standard Schema validation

Date: 2026-10-02 · Status: Accepted (revised during the Phase 0 remediation pass, before Phase 0 approval)

## Context
The spec requires server-side DTO/schema validation, OpenAPI documentation, a type-safe frontend contract and no duplicated validation. Zod is mandated for frontend forms.

Facts verified on 2026-10-02:
- `nestjs-zod` 5.5.0 peers `@nestjs/common ^10 || ^11` — **incompatible with NestJS 12** (npm registry metadata).
- NestJS **v12.0.0 release notes** (github.com/nestjs/nest/releases/tag/v12.0.0) introduce first-class **Standard Schema** support: `@Body()`, `@Query()`, `@Param()`, `@RawBody()` accept a `schema` option; a `StandardSchemaValidationPipe` validates against it; `StandardSchemaSerializerInterceptor` + `@SerializeOptions({ schema })` validates/transforms responses; "the same schemas feed OpenAPI generation". The class-validator workflow remains supported.
- Zod 4 implements the Standard Schema interface.

An earlier draft of this ADR proposed an in-house `ZodValidationPipe`; that is superseded by the native framework capability.

## Decision
- All request/response schemas live in `packages/validation` as Zod 4 schemas (`.strict()` for inputs).
- API controllers use NestJS 12 native Standard Schema validation (`@Body({ schema })`, global `StandardSchemaValidationPipe`) and `StandardSchemaSerializerInterceptor` for response shaping, so raw persistence models are never serialized.
- OpenAPI is generated by `@nestjs/swagger` 12 from the same schemas. If any construct is not rendered correctly, a thin helper converting with Zod 4's `z.toJSONSchema()` is the documented fallback (validated in Phase 1, item P1-7).
- Validation failures are mapped by the global exception filter to the standard error envelope (`VALIDATION_FAILED`, field-level `details`).
- Web forms use the same schemas through `@hookform/resolvers/zod`.
- `class-validator` / `class-transformer` are **not** installed (both are optional peers of `@nestjs/common` and `@nestjs/swagger`).

## Consequences
- One schema per contract, used by API validation, response serialization, OpenAPI and web forms.
- No dependency on an incompatible third-party bridge; minimal owned glue (error mapping only).
- Phase 1 must confirm the exact OpenAPI output quality for Zod 4 schemas through `@nestjs/swagger` 12.
